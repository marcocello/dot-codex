# Decision and evaluation scope

The authorized change preserves the existing lifecycle and narrows guidance at its handoffs. It does not change capture, fingerprint scope, concurrency ownership, deployment permissions, or the separate-authorship policy.

Motivating evidence: TWYD direct chat used a guessed MCP discovery contract until adjacent source was inspected; Giro shared-executor acceptance initially bypassed the worker producer; TWYD first-use vision defaults were tested from a state that concealed missing initialization; Arbitrator review found a visually unpainted yet clickable switch. Relevant interaction references are in the native parent chat. These histories motivate the evaluation; they are not claims that today's applications remain broken.

Compare the pre-edit instruction snapshot against candidate guidance on an isolated integration investigation. Candidate-only held-out review and lightweight repair check challenge completion overstatement and unnecessary ceremony. The author, trial workers, and final adjudicator are distinct from the implementer. No live provider, real credential, or external mutation is part of evaluation.

Expected benefit: pivotal assumptions investigated before acceptance; scenarios preserve actual starting state and consumer result; reviewers challenge original intent independently of PASS summaries. Regression risk: unnecessary investigation or process for clear repairs. No new document template, question quota, or universal live-provider requirement is introduced.

The records will distinguish observed behavior from integrity checks and retain failures. One sample cannot establish a success rate, token savings, or superiority over baseline. Host developer/tool context and explicitly supplied instructions remain shared evaluation limitations.
