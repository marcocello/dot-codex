# Markdown storage

Use the selected absolute root as storage scope; do not follow symlinks outside it. Inspect existing filename, directory and metadata conventions. Do not introduce categories, lifecycle states or a new organization system. With an empty collection, use a simple descriptive Markdown file appropriate to the request; ask only if placement or structure materially affects the user.

Authorized capture may create a missing root; review of an absent root reports that it is missing and writes nothing. Match relevant existing notes before a duplicate create. Preserve filenames, unrelated metadata and body when updating. Re-read before writing to detect concurrent changes; create exclusively or replace through a sibling temporary file as appropriate. Read saved content back. Uncertain writes require inspection before retrying.

The [Markdown capture reference](../../knowledge-capture/references/markdown-notes.md) handles note formatting. No automatic commit, push or publication. Explicit none is a separate disabled choice, not a Markdown fallback.
