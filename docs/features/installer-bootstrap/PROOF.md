# Bootstrap proof

Run `proof/run.sh` from the checkout. The check executes the actual Bash entry and helper with a disposable HOME and a constrained PATH. Python interpreter candidates delegate to a real compatible interpreter after the fixture package manager publishes one. Only OS discovery and apt/Homebrew/sudo are fixtures; no global installation occurs. Observe package calls, interpreter selection, unchanged files, forwarded arguments and exit status. Test terminal handoff through a real PTY and verify that redirected stdin cannot become prompt input.

C1–C3 use the public shell entry for missing/old/new Python, both OS paths, repeated setup, read-only plans, malformed options, absent configuration and unattended mode. C4 checks failed package installation, interrupted bootstrap, actual journal read-back and bounded download flags. C5 reuses the comprehensive setup proof as a separate affected regression, plus the legacy checkout/guided installer checks. Those journeys use real installer, context and durable files with provider, OS and service boundaries explicitly replaced.

This proves local bootstrap routing and preserved setup behavior. It does not establish live apt/Homebrew availability, a real Ubuntu installation, Azure provisioning, tenant consent, paired WhatsApp history or survival after reboot. The operator performs those steps on the target VM.

Adopt platform preflight, interpreter reuse/bootstrap, terminal isolation, dry-run, explicit stages, cleanup and success-after-verification. Preserve this project's state locks, credential isolation and cloud approval policy. Shell tracing, optional UI binary downloads and global npm profile edits do not help this setup and are omitted.
