# Independent semantic assessment

Author: independent acceptance author `/root/routing_proof`. Target: final knowledge-config, knowledge-connect, capture/review skills and linked routing, provider, credential and Markdown references. Method: inspect instructions against ordinary user paraphrases in frozen PROOF.md; no live services or actual model execution.

| Journey | Assessment |
| --- | --- |
| Save in an existing project with no config | Config retains pending intent, reuses explicit provider/workspace/target, asks only missing choices. Connection-only setup avoids unrelated destination questions. |
| Plugin absent | Connect distinguishes installed/connected/usable/capable, discovers real tools and plugin IDs, obeys installation-tool authorization and offers manual path when tooling is absent. Supported API is an alternative; no automatic installation. |
| User reports installation | Rediscovery and identity/access checks precede resume; unavailable refreshed tools are reported instead of claiming readiness. |
| MCP quota, use API | Exact-operation support checked; explicit user API request already answers switch question; matching credentials reused or guided setup performed; independent API limits disclosed. |
| New API token | Asks existing token vs guided generation; provider references and private terminal getpass procedure guide storage. Only a reference is persisted; unrelated token stores remain out of scope. |
| Temporary vs lasting preference | Resolve/client override changes no persisted transport; credentials attaches reference only. Persisted transport changes only when requested. |
| ClickUp Doc transcript | Unsupported Docs capability explicitly disclosed before proposing token setup; unsaved material and pending destination retained. |
| Possible previous write | Read-back/deduplication through stable identity/candidates precedes retry, including after approved transport switch; unresolved outcome forbids repetition. |
| Permission/authentication failure | Distinguished from quota; relevant access repair required, no transport workaround for permissions. |
| None/unrelated/local work | None avoids remote content; unrelated work does not trigger setup; explicit local/Zotero destination remains intact. |
| Organization neutrality | Config, connect, remote capture/review and shared routing impose no Tasks/Deals/Ideas, statuses, schema or hierarchy; legacy aliases are compatibility shortcuts. |

One residual linked-reference finding was sent to the implementation owner: markdown-notes.md required date/title and suggested rewritten body text despite existing plain-file conventions or exact-copy requests. The owner corrected the reference; independent reread confirms verbatim copy/archive, transformation only when requested, conditional metadata and optional formatting examples. The finding is resolved. All inspected journeys satisfy the frozen semantic acceptance at instruction level. Frozen FEATURE/PROOF/runner/test hashes were rechecked and remain unchanged.

Limits: this assessment verifies written operational guidance, not future model compliance, actual plugin installation, live credentials/permissions, quota behavior or newly installed tool refresh in a running host.
