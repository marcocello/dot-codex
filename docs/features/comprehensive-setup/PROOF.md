# Setup proof

Prepare the repository environment with the context `test,pinecone` extras, then run `proof/run.sh` from the checkout. Tests invoke the public CLI for plans and compatibility, then execute the actual host wizard with disposable HOME/state and external command fixtures. The real harness installer, inventory reconciliation, context application and persistent storage run in that journey; operating-system validation, package-manager installation, account CLIs and service management are explicit external fixtures. Independently inspect configuration, service definitions, phase receipts and private file permissions. Repeat and remove an installed resource to exercise reconciliation. A failed provider must retain an incomplete receipt and a nonzero result.

Azure checks execute the actual embedded VPN generator and configurator with real OpenSSL certificates and disposable filesystem roots. ARM and service management are fixtures. Repeating bootstrap must preserve the CA. A restored disk with another CA must fail without rotation. Protected request values must not enter argv or script text. Current-source export includes reviewed additions and deletions, excludes ignored credentials and arbitrary untracked notes, and refuses independent remote edits. Backend identity is checked before cloud mutation; Terraform apply requires explicit approval. These checks create no paid resources.

Context regressions retain the real embedding/Qdrant/MCP journey. Pinecone checks replace only HTTP with a stateful provider contract fixture. The installed Pinecone 10.2 SDK and actual multilingual ONNX embeddings verify namespace isolation, metadata filtering, backend migration, model mismatch, erasure and current local authorization. They do not establish live cloud availability or eventual consistency. MCP onboarding probes the real read-only server; registration also uses the installed native Codex CLI in a disposable home when available. Supported component and installer regressions run separately.
