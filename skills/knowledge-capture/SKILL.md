# Knowledge Capture

Resolve what to capture, whether the material is supplied or must be gathered, and where to save it. An explicit destination takes precedence over defaults. For configured or remote capture, resolve the saved connection through the configured capture reference, reusing any explicit provider or target. For other capture modes, use established context when unambiguous; otherwise ask one concise destination question before writing. A URL alone does not authorize an archive or another stored record.

## Choose one destination

Read only the selected mode reference:

- **Markdown collection, diary, journal, or local note file:** [Markdown notes](references/markdown-notes.md). Discover and preserve that collection's conventions.
- **Configured connection or remote document/collection:** [Configured capture](references/second-brain.md). Preserve the requested content and destination; connect/setup handles missing plugins, tokens and transport recovery.
- **Article or video archived in Zotero:** [Research sources](references/research-sources.md). Preserve source evidence and grounded highlights through the installed Zotero companion.

A simple supplied note does not trigger an external sweep. Gather external sources only within the requested scope. Saving in one destination does not authorize saving elsewhere; use multiple destinations only when requested.

For exporting Codex dialogue and interaction history, use the separate explicitly invoked `harness-capture-interactions` skill. This skill captures knowledge or derived outcomes, not the interaction-history archive.

## Receipt

Distinguish verified saves, unverified write attempts, and prepared proposals. Report the saved file or record identity, destination, and meaningful limitations. Do not expose sensitive note contents or full transcripts in the receipt by default.
