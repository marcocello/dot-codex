# Knowledge routing contract

Resolve the explicit operation/chat profile or saved default through knowledge-tool-connect before configured knowledge operations. Explicit choices do not silently alter defaults. Missing config asks and resumes; invalid config is not automatically replaced. Standalone local notes and Zotero keep their explicit destinations; unrelated work does not trigger setup.

A remote profile binds provider, connection identity, account and workspace. It may hold a default destination, preferred transport and API credential. Destinations follow the user's organization: no mandatory Tasks/Deals/Ideas, statuses, confidence labels or directory structure. Historical alias keys are optional shortcuts only. Resolve identity and destination ambiguity before access, without repeating choices already made.

knowledge-tool-connect owns provider operations and capability assessment, including missing-plugin and MCP-limit recovery. Only offer an alternative that supports the operation. User-selected API access may reuse saved credentials without changing default transport. Verify account/workspace and destination; access to other accounts is not a fallback.

Capture preserves supplied material or the requested summary/extraction. Gather external sources only within explicit scope. Do not invent fields, dates, owners or commitments. Match relevant existing content before a potentially duplicate create, preserve unrelated content on update and read back writes. An uncertain outcome must be reconciled before retrying.

Review reads the requested scope without changing it. Multiple profiles are included only when requested; retain provenance and report inaccessible sources. Neither setup nor review authorizes unrelated writes or publication.

Markdown follows [the local adapter](markdown.md). Explicit none performs no storage or stored-state review. Report exact unsaved proposals where useful, never claim success from a prepared payload alone.
