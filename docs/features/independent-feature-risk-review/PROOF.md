# Independent Feature Risk Review Proof

## Done
- Preflight and final evaluation receive verbatim user goals and corrections.
- Parent-supplied paths are discovery entry points rather than scope ceilings.
- Both reviewers independently follow relevant current authority, consumers, states, schemas, persistence, runtime/provider, interaction, and call paths.
- One bounded preflight returns every supported material finding without a numeric cap and without becoming a repeat-until-clear gate.
- Existing lifecycle, consolidated-evaluation, queue, and completion guarantees remain compatible.

## Command

```bash
"${CODEX_HOME:-$HOME/.codex}/scripts/proof_run_capture" --feature-dir docs/features/independent-feature-risk-review --timeout-seconds 60 --note "verify independent bounded feature risk discovery"
```

## Scenario: Preflight independently discovers relevant contract risk
- Producer/activation: pytest reads the global kernel, feature execution owner, preflight skill, and preflight prompt.
- Consumer: tracked/autonomous implementation entry.
- Read-back: assertions require verbatim user goal/corrections, independently discovered current authority and affected consumers, parent paths as entry points, all supported material findings, and no numeric cap.
- Fake: none.
- Catches: reviewing a lossy parent paraphrase, accepting a curated file list as complete scope, stopping after three findings, or missing a related schema/state consumer.

## Scenario: Final evaluator independently validates the accepted outcome
- Producer/activation: pytest reads feature execution, evaluator skill, and evaluator prompt.
- Consumer: final semantic judgment after passing realistic proof.
- Read-back: assertions require verbatim user goals/corrections at evaluator invocation, the active-feature surface to be an entry point, independent discovery of relevant current contracts/consumers/state paths, and one consolidated verdict containing all supported material findings.
- Fake: none.
- Catches: a proof/evaluator pair sharing the parent's incomplete consumer map or treating changed files as the entire architecture.

## Scenario: Review remains bounded and non-ceremonial
- Producer/activation: pytest runs existing preflight, bounded-evaluation, and lean-lifecycle policy suites alongside the new regression.
- Consumer: accountable parent and queue completion.
- Read-back: assertions preserve fresh separate read-only review, no repeat-until-clear preflight, no extra evaluator stage, no durable receipt, and completion only after realistic proof plus fresh evaluator `PASS`.
- Fake: none.
- Catches: replacing the old cap with an unbounded repository sweep, a second approval gate, persisted review state, or reviewer-owned mutation.

## Scope
Proves:
- The active instruction surface requires independent, relevance-bounded review discovery and removes the obsolete preflight quota.
- Existing serial proof/evaluator completion behavior remains intact.

Does not prove:
- That every future reviewer will identify every relevant path or defect.
- Product-specific review quality in an arbitrary repository.
- Runtime behavior beyond this instruction-policy boundary.

False-green risks:
- Static policy checks cannot guarantee future reviewer judgment.
- A newly phrased scope restriction could evade exact assertions; semantic evaluation remains required.

Evidence method:
- deterministic

Known gaps:
- Reviewer discovery quality remains probabilistic.

## Environment
- Repository-local Python and pytest.
- No network, credentials, external mutation, or candidate product implementation.
