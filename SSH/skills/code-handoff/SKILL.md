# Handoff

Create the minimum self-contained context another agent needs to continue: the user's outcome and authority, settled decisions, relevant paths and runtime, current edits and ownership, evidence with its limits, failed approaches worth avoiding, unresolved questions, and the next useful action. Include only what matters to that action. Do not copy credentials or the entire conversation.

Use existing project notes or native task history when they serve the need. Write a persistent file only when requested or when authorized ongoing work needs a checkpoint; reuse one current note instead of accumulating logs. If history is partial, say so.

Use native continuation, fork, or delegation tools when available and authorized by the session. Create a separate task only when the user requests one. Otherwise provide the handoff in the current conversation. A context note does not transfer permissions, start work elsewhere, or implement session branching.

On resume, recheck the current files, revision, runtime, and pending decisions before relying on the note. Previous checks are historical if relevant inputs changed. Continue from the current state rather than repeating completed discovery or treating a handoff as completion.
