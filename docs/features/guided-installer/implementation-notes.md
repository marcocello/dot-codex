# Implementation and verification context

The user requested a usable guided installer with independent or combined phases, home copy/merge/replacement, CLI installation, pairing, and safe Ctrl+C behavior. The existing dot-codex installer and the embedded codex-on-vm console were inspected. OpenClaw's shell installer and TypeScript `@clack/prompts` wizard were read through their primary source files on 2026-10-24. The delivered entrypoint stays in dot-codex; codex-on-vm is a reference and was not modified. Backup retention is the reversible replacement default.

The implementation separates coordination (`install.py`), filesystem undo/checkpoints (`install_state.py`), package and service setup (`install_runtime.py`), and the copied persistent runner (`install_service.py`). The persistent runner and managed CLI live outside the activated checkout. Existing dependency orchestration remains in the original inventory manager.

The original checkout-installer fixture now copies the extracted modules, and its recorded fake CLI reports the version used by the new post-activation check. Its assertions and native plugin/MCP read-back remain intact. The new service-definition assertion was corrected before final proof to expect the VM's managed daemon bootstrap lifecycle rather than the older foreground command. A synchronization marker in the fake package was corrected because broad version substitution had accidentally renamed the marker variable. Neither correction changes the promised observable result or hides a provider boundary.

Final review added coverage for retry choices: optional integrations survive a provider failure, explicit command-line overrides take precedence over saved defaults, custom download URLs require re-entry rather than being stored, and a final doctor-only retry updates the checkpoint. These are required recovery behaviors, not a change in the real/fake boundary.

Initial acceptance failed against the former installer. Final evidence uses public CLI invocations and independent read-back. It includes actual Ctrl+C and SIGKILL during filesystem activation, recovery under the next lock, CLI publication cancellation, full composed installation, native marketplace regression, official package download in a disposable macOS HOME, and the same isolated journeys in a temporary Linux tree on media.local. Network/account and service-manager providers in the composed journeys are fakes; official package downloads and native plugin regression use the real providers described in PROOF. No real host service, authentication, pairing, or reboot is performed by these checks.
