# Four lifecycle skills proof

## Done

The checkout exposes four automatically invocable lifecycle skills, retires the generic workflow entrypoint without introducing Analyze, retains direct specialist analysis and lifecycle safeguards, and supplies usable current instruction links and unchanged operational support. This proof establishes on-disk readiness; a fresh Codex task must reload the catalog before application discovery can be claimed.

## Command

Run `bash docs/features/four-lifecycle-skills/proof/run.sh` from this checkout. Official attempts use `proof_run_capture.py --feature-dir docs/features/four-lifecycle-skills`. Before a final attempt, the independent proof author reads the changed instruction surface and writes `evidence/semantic-assessment.json`, containing independent role identity, current `check_split.py --fingerprint` input hashes, and a result for every frozen scenario in `proof/scenarios.json`. Every result contains the selected route, verdict, evidence citations, and an outcome for each supplied paraphrase. This result is retained evidence rather than an editable acceptance input. A missing, stale, or failing assessment fails the runner.

## Scenarios and dedicated tests

All executable assertions live in `proof/check_split.py`; `proof/run.sh` executes that one dedicated boundary test. `proof/baseline.json` preserves the pre-migration inventory, historical feature contract and runner hashes, and operational helper digest. `proof/scenarios.json` freezes twelve distinct semantic cases, each with two wording variants and required scope outcomes.

The repository owns skill discovery and current instructions. Its agent consumer is the primary consumer; specialist skills and runtime operators are affected consumers. Relevant states are new discovery, pre-existing inventory/history, known defects, running-system symptoms, ready and active Ship, diagnosis-only requests, and changed acceptance. External production mutation is the unsafe edge and is neither performed nor simulated by this documentation migration proof. The most plausible central break is a discoverable new skill whose instructions omit a crucial old scope or completion rule; independent semantic review addresses this rather than exact-prose matching.

## Proves

The real local inventory boundary and filesystem discovery surfaces expose the accepted four-skill organization. Current consumers can follow the migrated links. The operational helper is preserved and callable. An independent reading of the actual instructions yields the accepted routing and scope outcomes across wording variants, including specialist and ordinary explanation requests.

## Does not prove

This does not exercise a fresh Codex process, guarantee every future model follows the instructions, prove operational recovery of a real service, or re-prove historical features. It does not equate a gate or broad regression pass with acceptance. Markdown destination existence does not itself validate all fragment anchors; independent reading checks the decision-bearing guidance and final review must catch unusable anchors.

## False-green risks

Semantic evidence is a human/agent assessment, not a deterministic model benchmark. Hash binding detects stale evidence but cannot prevent a writer from fabricating a verdict; separate authorship and the final read-only reviewer provide the role separation. Structural tests cannot independently establish semantic preservation. The final reviewer must inspect the assessment and the actual changed guidance, not merely its PASS markers.
