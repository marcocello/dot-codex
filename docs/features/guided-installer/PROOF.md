# Guided installer verification

Run `bash docs/features/guided-installer/proof/run.sh` from the repository root. The runner invokes the real public `install.sh` in disposable checkouts and homes. Filesystem, Git, shell activation, package extraction, digest verification, publication, rollback, checkpoints, and signal handling are real. Test package executables implement the documented CLI boundary; downloads, sign-in, pairing, systemd, and launchd are isolated outer providers.

AC1 uses plain-input and pseudo-terminal wizard journeys, default-No phase skipping, default-No final confirmation, invalid-answer retry, explicit restricted step lists, dry-run, EOF, and cancellation. AC2 uses Git source read-back, conflicting files, internal and foreign links, an existing CLI publication, and failed activation. AC3 reads the executable after fresh/repeated/version-changing installations and rejected archives. AC4 sends a real signal while the installer is awaiting input or executing a controlled subprocess, checks the old home and publication, and resumes through the public command. AC5 reads provider calls and checkpoint contents. AC6 independently reads generated service definitions and checks failure versus connected provider responses. AC7 is checked against the actual help and maintained installation documentation. AC8 reads actual terminal output and piped output, including the English banner, step titles, labeled plan, OpenClaw-style status marks and blue accent, wide/narrow terminal banner framing, forced/disabled colors, TERM=dumb, and NO_COLOR suppression.

The existing checkout-installer suite is an affected regression and retains its real Codex marketplace/MCP read-back. These checks do not establish an actual reboot, a live relay connection, real account authentication, or native service-manager activation. Those operations are exposed to the operator and must not be described as verified on media.local.

Run `bash docs/features/guided-installer/proof/native-package.sh` as supporting verification for real official-release download, digest checking, archive extraction, executable version, repeated publication, native managed-path resolution, and actual app-server start/version/stop on the current platform. It stops its daemon and removes the disposable home on exit. It does not activate this checkout, install host services, or sign in.

`python3 docs/features/guided-installer/proof/linux-fixture.py --host media.local` copies only the installer source and fixtures into a temporary Linux tree and runs the same journeys there. Add `--native-package` to exercise the official package and native app-server lifecycle in a disposable home instead. Both temporary trees are removed; the real media.local installation and services are not changed.

The service-manager fixture executes the generated systemd bootstrap command with its declared environment. Its isolated Codex provider enforces the fixed managed path observed in the pinned native daemon source. AC6 also covers publication of that path, retention of conflicting legacy package directories, and refusal of a different custom CLI. Real native app-server checks complement this boundary; actual host service activation, account sign-in, relay connection, and reboot verification remain separate authorized operational checks.
