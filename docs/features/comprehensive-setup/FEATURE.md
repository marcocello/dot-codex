# Comprehensive setup

The operator runs `./secondbrain.sh setup` from a checkout. The same wizard prepares an Ubuntu VM directly or provisions Azure from macOS and continues inside the VM. Existing `install` and `vm` commands remain available.

- C1: A read-only `--plan` explains both entry modes, installation, selected scopes, authentication, supervision and verification. Explicit `--component` retains the dependency-only interface.
- C2: Host setup installs prerequisites, a persistent harness checkout, Codex, every declared skill/plugin, both Python applications and the optional Baileys runtime. Repeating setup probes actual resources, preserves configuration and private data, and repairs missing resources. A concurrent setup cannot mutate the same state.
- C3: The wizard collects one Outlook account and explicit WhatsApp chat IDs, authenticates through the existing adapters, configures the read-only context MCP, and supervises ingestion, WhatsApp sync and selected gateways. Credentials stay outside receipts and command lines. Missing logins or failed services produce a nonzero incomplete result with resumable state.
- C4: Qdrant is the default. Optional Pinecone uses a dedicated namespace, local embeddings and an operator-selected existing index or explicitly approved cloud index creation. Remote search rechecks current local scopes and revisions. Backend changes enqueue a rebuild; model mismatch never deletes an existing cloud index. Deletion does not require an embedding model.
- C5: Azure mode installs client prerequisites, configures state storage, shows a Terraform plan and requires explicit approval before creating paid resources. It prepares the persistent disk and SSH host trust through the Azure agent, bootstraps missing VPN credentials without public SSH, and runs the same host wizard over verified VPN SSH. Interrupted provisioning resumes against the existing state.

The implementation is verified locally using real configuration, durable files, subprocess entrypoints, local embeddings and Qdrant. Azure, operating-system installation, device authentication and Pinecone are replaced only at their external boundary in isolated checks. Live tenant consent, real WhatsApp history, Azure deployment, cloud Pinecone consistency and reboot survival require the operator's accounts and target VM; local proof does not establish those results.
