# Harness Evolution

1. Read the retained proof attempts, evaluator findings, and material user corrections together.
2. Name the repeated failure or demonstrated central false green.
3. Separate the repository problem from the reusable harness problem.
4. Pick one owner: skill, doc, script, test, or config.
5. Make the smallest change that alters the failing decision boundary.
6. Add the motivating regression and one compatibility or held-out check.
7. Keep, revise, or revert from actual results.

No change manifest. No transition schema. Retained attempts + diff + tests + short reason suffice.
