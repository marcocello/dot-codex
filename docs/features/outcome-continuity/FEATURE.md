# Outcome continuity from discovery to completion

## Outcome and scope

Improve the existing coding workflow so a consequential assumption cannot silently become both the implementation contract and its passing oracle. Preserve Partner -> specification/independent proof -> implementation -> independent review; add no mandatory stage, artifact, approval round, or live-provider requirement.

The user authorized improving the workflow after reviewing Giro, TWYD Portal, and Arbitrator. This slice changes only guidance for investigation, scenario handoff, proof authorship, and completion review. Fingerprint selection, worktree tooling, capture redaction, and application code remain separate work.

## Accepted behavior

- Partner investigates the concrete starting state, normal activation, and intended consumer result, proportionate to the task. It resolves pivotal discoverable facts from available repository/provider evidence before dependent acceptance; unavailable facts remain explicit limits. Product questions remain about consequential user choices, not discoverable implementation details.
- Specifications and proof preserve user decisions, evidenced engineering facts, and material assumptions distinctly. A central unsupported provider assumption cannot be made true by writing a fake. No new mandatory template or evidence ledger is required.
- Independent proof authors derive observable scenarios from original intent and real starting states, then reconcile with the proposed contract. They challenge plausible incomplete implementations while retaining useful reuse and outer-edge fakes.
- Independent reviewers form an outcome expectation from original requests/corrections before using supplied PASS results. They investigate shared assumptions and the gap between the tested target and claimed completion. A provider unavailable to the reviewer limits the verdict rather than requiring unauthorized delivery.
- Clear local repairs and already-understood work continue without new questions, documentation scaffolds, or investigation unrelated to the change.
- Reuse existing instructions and replace redundant prose where practical. Changes must be justified by observed evaluation, with no claim that a single trial establishes improvement frequency.

## Acceptance

Independent acceptance uses isolated fresh-worker executions with raw requests and source artifacts, withheld expected answers, retained baseline and candidate observations, and a distinct adjudicator. Include a discoverable integration-contract case, an unseen completion-review case, and a clear repair control. Judge investigation, artifacts, conclusions, and unnecessary pauses rather than wording. No external mutation or production services.
