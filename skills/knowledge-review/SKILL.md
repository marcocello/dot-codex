# Knowledge Review

Resolve the selected connection/default through [knowledge-tool-connect](../knowledge-tool-connect/SKILL.md). Reuse explicit provider, workspace and destination choices. Missing setup asks and resumes the pending review; none produces no stored-state review. Delegate remote reads to [knowledge-tool-connect](../knowledge-tool-connect/SKILL.md), including plugin/API choices and recovery from unavailable MCP. Markdown uses the configured local root.

Review the requested collection, document, topic or time window. Use a saved destination when applicable; ask only when scope is missing or materially ambiguous. Do not expand to all accounts or create a Tasks/Deals/Ideas taxonomy. An explicitly requested multi-profile review enumerates configured profiles separately, retaining provenance and reporting inaccessible ones.

Match the user's purpose: a brief highlights relevant information and open questions; a weekly review uses the requested period and existing organization. Neither implies scheduling, prescribed lifecycle states or changes to stored records. Separate source facts from interpretation and suggestions; do not invent dates, owners or commitments.

Review is read-only unless the user requests specific changes. Updates use the selected connection and existing schema, preserve unrelated content and require read-back. Missing access yields an honest partial review or exact limitation, not invented content. Keep receipts concise and avoid reproducing sensitive source bodies.
